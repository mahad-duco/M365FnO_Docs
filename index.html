Refresh the UAT database from PROD

A refresh replaces the UAT database and removes existing UAT data. It does not deploy application code. Schedule it off-peak and confirm the source and target carefully.

Important: Copying production data during business hours can affect production. Run one refresh at a time.

Export the database as a BACPAC and download it

Use this when you need a copy of a sandbox database outside LCS, for example to restore it on a Tier 1 developer environment. The export runs against the source sandbox and can take hours.

Limits: LCS exports fail above 50 GB. Microsoft advises against exporting databases above 200 GB. For larger databases, use a refresh instead.

Import the BACPAC and rename the databases

Import under a new name, keep the current database, then swap the names. Replace the placeholders in the commands with your values.

Placeholders: <bacpac-file>, <target-server>, <new-db>, <sqlpackage-folder>. The database names AxDB, AxDB_OLD, and <new-db> must match your environment.

Import

SqlPackage.exe /a:import /sf:<bacpac-file> /tsn:<target-server> /tdn:<new-db> /p:CommandTimeout=20000 /TargetEncryptConnection:False

Rename

Stop first: Stop the AOS services and IIS before running the rename. Otherwise the AOS can reconnect to AxDB during the rename.
-- Disconnect users from the current database
ALTER DATABASE AxDB SET SINGLE_USER WITH ROLLBACK IMMEDIATE

-- Rename the current database to AxDB_OLD
ALTER DATABASE AxDB MODIFY NAME = AxDB_OLD

-- Put AxDB_OLD back in multi-user mode
ALTER DATABASE AxDB_OLD SET MULTI_USER WITH ROLLBACK IMMEDIATE

-- Rename the imported database to AxDB
ALTER DATABASE [<new-db>] MODIFY NAME = AxDB

Reference: Import the database and update the database

Rollback

If the refreshed database fails, AxDB_OLD still holds the previous data. Rollback is only clean until the new AxDB is written to.

ALTER DATABASE AxDB SET SINGLE_USER WITH ROLLBACK IMMEDIATE
ALTER DATABASE AxDB MODIFY NAME = AxDB_FAILED
ALTER DATABASE AxDB_OLD SET MULTI_USER WITH ROLLBACK IMMEDIATE
ALTER DATABASE AxDB_OLD MODIFY NAME = AxDB
Warning: Rollback loses any data entered in the new AxDB after the import. Once sign-off happens, drop AxDB_OLD to free disk space.

Notes

  • Sequence matters: refresh UAT, deploy and test in UAT, mark the release candidate, then deploy that same update to PROD. Use the BACPAC steps only when a database copy is needed outside LCS.
  • LCS menu names and prompts can change between releases. Check your screen if a label differs.
  • Power Platform-managed environments use a different process and aren't covered here.
  • Replace the placeholders in angle brackets with your own values before running any command.

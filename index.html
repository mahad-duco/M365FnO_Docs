Before you start

Confirm these before touching any environment. Database steps change live data, so confirm the target every time.

References: Cloud operations and servicing

Refresh the UAT database from PROD

A refresh replaces the UAT database and removes existing UAT data. It does not deploy application code. Schedule it off-peak and confirm the source and target carefully.

Important: Copying production data during business hours can affect production. Run one refresh at a time.

After the refresh

References: Refresh database

Restore user access and request JIT access

After a refresh, normal users are disabled. The administrator and certain internal service accounts remain available.

Enable approved UAT users

Request temporary database access (JIT), only if approved troubleshooting needs it

JIT grants temporary database access. It does not enable F&O users or assign roles. Use the application screen above for normal user enablement.

Warning: Don't use blanket SQL updates to enable users or change roles. Database changes need an approved, supported procedure. The firewall entry expires after eight hours or a database replacement, whichever comes first. Observe the displayed account expiry.
